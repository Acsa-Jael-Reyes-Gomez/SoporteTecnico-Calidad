# Diagnóstico inicial

Antes de trabajar en la calidad revisé una copia del Sistema de Soporte Técnico. Ya era una aplicación de escritorio con módulos de tickets, técnicos, rutas, equipos y reportes.

## Lo que encontré

- El sistema tenía código y funcionalidades existentes que debían conservarse.
- Había pruebas definidas, pero no se contaba con resultados históricos completos ni una medición inicial de cobertura comparable.
- Hacía falta un proceso automático y ordenado para compilar, probar y revisar cada cambio.
- Era importante separar las pruebas de la información real.

## Qué decidí hacer

Trabajé en una copia, utilicé datos ficticios y organicé un pipeline con pruebas, análisis y reportes. El estado final se explica en el [reporte de mejora](Reporte-Mejora.md).

**Nota:** este documento describe el punto de partida, no los resultados actuales.
